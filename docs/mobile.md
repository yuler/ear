# 手机端:局域网镜像设计

状态:原型阶段。交互原型在 `prototypes/ios/`,确认后再用 nsh 的 iOS/Android 目标实现。

本版只做手机端。电脑端(桌面 App)怎么接入,放到「待决定」里,不在这一版范围内。原型右侧画的电脑面板只是为了模拟对端。

## 目标

- 手机端只做一件事:把电脑上已经下载好的视频和字幕镜像到手机,离线播放。
- 手机端不解析链接,也不从 YouTube 下载。下载只在电脑上做。
- 尽量少操作:配对一次之后,回到同一个 Wi-Fi 就自动同步,不需要手动点「同步」。

## 角色

- **电脑(Server)**:Ear 桌面端,是媒体库的唯一来源。它在局域网里提供镜像服务。
- **手机(Client)**:Ear 手机端,镜像电脑上的媒体库。
- **多对多**:
  - 一台电脑可以配对多台手机或平板,各自独立镜像。
  - 一台手机可以配对多台电脑,比如家里一台、公司一台。

## 配对

只走局域网。配对时电脑上不需要点「允许」:二维码是一次性的、只显示在电脑屏幕上,能扫到就说明人在电脑旁边。

1. 电脑「设置 → 手机镜像」显示二维码和 4 位配对码。
   - 二维码内容:`ear://pair?transport=lan&host=<ip>&port=<port>&code=<配对码>`。
   - 配对码 2 分钟过期后自动刷新,用过一次也会立即刷新。
2. 手机打开全屏扫码页。第一次打开时,先依次请求两个系统权限:
   - **相机**:用来扫码。拒绝后,扫码页显示「需要相机权限才能扫码」、「去设置开启」,以及「手动输入配对码」。
   - **本地网络**(iOS 14+):用来找到并连接电脑。拒绝后,扫码页、首页状态条和设置里都会提示,并给出「去设置开启」。
3. 对准二维码后自动识别,取景框变绿,随即完成配对。
4. 成功:显示对勾和「已配对」,约 1 秒后自动回到媒体库,开始镜像。
5. 失败(不在同一个 Wi-Fi):显示原因、「重试」和「手动输入配对码」。
6. 扫一台已经配对过的电脑,不算错误,直接显示「已连接」,然后回到媒体库。

**手动输入(扫不了码时的备用方式):**
1. 在扫码页点「无法扫码?手动输入配对码」。
2. 列出同一个 Wi-Fi 里打开了 Ear 的电脑(通过 Bonjour 发现),选一台。
3. 输入电脑二维码旁边显示的 4 位配对码,输满 4 位自动提交。输错时输入框会抖动,并提示「配对码不对」。

解除配对有两种方式,两种都会保留手机上已经下好的副本:
- 手机端:在「设置 → 已配对的电脑」里点「断开」。
- 电脑端:在「已配对设备」里点「移除」。被移除的手机会看到提示。

## 多台电脑

典型场景:白天连公司电脑,晚上连家里电脑,两边的视频都传到同一部手机。

- **不需要手动切换。** 手机连上哪个 Wi-Fi,就自动连接那个网络里已配对的电脑。如果两台电脑在同一个网络,两台同时连。
- **只有一个媒体库。** 所有电脑的视频合在一起显示,每个条目标出来源,比如「家里」「公司」,或者「家里 · 公司」。
- **同一个视频只传一次。** 用 `videoId` 去重:家里已经传过的视频,在公司不会再传一次。
- **换网络时不丢进度。** 正在传的文件如果它的电脑突然连不上了,已传的部分会保留,条目回到等待状态。之后不管连上哪台有这个视频的电脑,都从断点继续传(HTTP Range),不会从头开始。
- **不在当前网络的电脑。** 它的视频显示「在家里 · 待连接」,回到那个 Wi-Fi 后自动镜像。
- **断开某一台电脑。** 只影响这台电脑:它独有、还没传完的条目会从列表消失;已经下好的副本保留,标为「来自家里」。

## 镜像规则

- **镜像范围**:默认镜像每台已配对电脑的全部媒体库(视频和字幕)。
- **新增视频**:电脑上新下载的视频会自动排进队列。
- **并发**:每部手机最多同时传 3 个文件,这个上限对所有电脑一起算(手机的带宽是共用的)。
- **中断**:断开 Wi-Fi、本地网络权限被关闭,或关闭后台同步后切到后台时,正在传的文件暂停,已传的部分保留,条件恢复后从断点续传。解除配对时,如果其他已配对的电脑也有这个视频,也保留进度;否则丢弃。
- **优先**:点一个还没传完的视频,它会排到最前面。如果 3 个位置都占满了,它会顶掉一个普通的传输(被顶掉的暂停并保留进度)。
- **后台**:「后台同步」默认打开,App 切到后台后镜像继续进行,用实时活动(Live Activity)或通知显示总进度,例如「后台镜像中 4/6」。关闭后,切到后台就暂停,回到 App 后继续。
- **删除**:在手机上左滑删除,只删手机上的副本,不影响电脑。删除后底部出现提示「已删除『…』· 撤销」,4 秒内可以撤销。被删的条目移到「仅在电脑上」分组,不会再自动镜像,点「重新镜像」可以恢复。

## 手机端界面

### 媒体库(首页)

- **顶部**:左边是标题「Ear」,右上角是设置按钮(⚙)。首页不放配对列表。
- **没有配对时**:首页只显示一个快速配对入口,包括「连接电脑」、一句说明和「扫码配对」按钮,点了直接打开扫码页。
- **已配对但电脑上没有视频时**:显示「电脑上还没有视频」,不显示配对入口。
- **配对后的状态条**,按情况显示一种:
  - 本地网络权限已关闭(附「去设置开启」)
  - 没有连上已配对的电脑(附上当前 Wi-Fi)
  - 镜像中 N/M · 同时 K 个 · 从哪些电脑拉取(附总进度条)
  - 已与哪些电脑同步。如果还有其他电脑上的视频没传,会说明还有几个。
- **列表**:每行是一个视频,显示封面、时长、标题、状态标签、来源和文件大小。
- **状态标签**:
  - 已离线
  - 镜像中 xx%(封面底部还有一条进度线)
  - 等待镜像
  - 下一个(用户点过,排在最前)
  - 在家里 · 待连接
  - 重新镜像(按钮)
- **点击视频**:
  - 已离线:打开详情页。
  - 还没传完:排到最前面优先镜像,并用提示说明当前状态,例如「正在镜像 45%,完成后就能播放」「已优先镜像」「在家里的电脑上,连上那里的 Wi-Fi 后优先镜像」。
- **左滑**:露出「删除」按钮,滑得够长直接删除,可以撤销。底部那句「左滑删除」的提示只在用户第一次滑动之前显示。

### 设置(底部弹窗)

点首页右上角的 ⚙ 打开,内容从上到下:
- 外观:深色 / 浅色 / 跟随系统(默认跟随系统)。配色和 `app/theme.json` 一致。
- 语言:中文 / English。界面文字全部跟着切换。
- 后台同步:开关,默认打开。
- 已配对的电脑:
  - 每台电脑一行,显示名称、是否已连接、所在网络、已传数量(N/M),以及「断开」按钮。
  - 列表底部有「＋ 配对新的电脑」,点了关闭弹窗,打开扫码页。
- 底部一句说明:连上哪台电脑的 Wi-Fi,就自动从哪台镜像;所有视频在同一个媒体库里。

### 配对页(全屏)

- 黑色相机画面,中间是取景框,框内有扫描线;左上角是「取消」。
- 权限、扫码、成功或失败,全部在这一个页面里完成,中间不跳转(步骤见上面的「配对」)。
- 系统权限弹窗按 iOS 的样式画:相机用「不允许 / 好」,本地网络用「不允许 / 允许」。
- 原型里点「去设置开启」,等于模拟用户在系统设置里打开了权限,然后直接回到 App。
- 手动输入页:左上角是「‹ 扫码」,可以返回扫码;中间先列出附近的电脑,选好后是一个 4 位数字的输入框。

### 详情页(播放器)

- **进入动画**:和桌面端一样,封面从卡片位置放大并移动到视频区域(参考 `app/views/viewTransition.ts`)。同时媒体库淡出,播放器淡入。封面在视频区域停留片刻后淡出,开始播放。
- **返回动画**:视频区域缩回到原来那张卡片的封面位置。
- **布局**:上下布局,16:9 视频固定在上方,下方是跟随播放滚动的字幕,底部是一排拇指可及的控制按钮。
- **控制按钮**:盲听遮罩、上一句、播放/暂停、单句循环、下一句。右上角调倍速(0.8 / 1.0 / 1.2 / 1.5)。
- 点击字幕行,跳到那一句播放。

## 电脑端(对端,本版不实现)

原型右侧的电脑面板只用来模拟对端。手机端依赖电脑提供以下能力:
- 「设置 → 手机镜像」里显示二维码,以及「无法扫码时,在手机上输入配对码」的 4 位数字;
- 已配对设备列表,可以移除设备;
- 在局域网里通过 Bonjour 广播自己,让手机能发现它。

## 传输层与中继器

- 代码里有一个 `Transport` 接口,包含 `kind`、`address`、`pairUrl`。目前只实现 `lan`。
- **中继器(预留)**:以后可能支持用户自定义的中继服务器,用于手机和电脑不在同一网络的情况。
  - UI 上暂不显示。
  - 代码在 `relay` 的位置标 `TODO(relay)`,通过 `createTransport()` 选择传输方式。
  - 二维码内容已经带了 `transport=` 参数,所以现在生成的二维码以后仍然可用。

## 原型

用浏览器直接打开 `prototypes/ios/ios-mvp.html`,不需要构建,所有状态只保存在内存里。

**文件:**
- `ios-transport.js`:`Transport` 接口(只有 LAN,预留了 `TODO(relay)`)
- `ios-i18n.js`:手机界面文案(中文 / English)
- `ios-sync.js`:配对和镜像引擎,不依赖 DOM
- `ios-mac.js`:电脑端面板(家里 / 公司两台,可以切换)
- `ios-player.js`:详情页播放器
- `ios-transition.js`:封面 → 视频的转场动画
- `ios-settings.js`:设置弹窗
- `ios-scan.js`:配对页(系统权限、扫码、手动输入配对码)
- `ios-mvp.js`:媒体库、手势、提示(含撤销)、启动
- `ios-mvp.css` / `ios-mirror.css`:基础样式 / 镜像、设置、扫码、转场样式
- `ios-mvp.test.cjs`:引擎回归测试,用 `node --test prototypes/ios/*.test.cjs` 运行,CI 也会跑

**顶栏的模拟按钮:**
- 手机 Wi-Fi:在家里 / 公司 / 外出之间切换。
- 切到后台。
- 右侧电脑新下好 1 个视频。
- 其他设备配对到右侧电脑。

外观、语言和后台同步在手机的设置弹窗里切换。

**原型没做的部分:**
- 二维码是假的,不能真扫。
- 没有真实网络传输,也没有加密和认证。
- 其他设备的镜像进度是模拟的。

## 待决定

**手机端:**
- 被删除的副本:是一直不再自动镜像(原型目前这样处理),还是电脑上有更新时重新镜像?
- 电脑上删除了一个视频:手机上的副本是保留,还是跟着删除?
- 每部手机同时传 3 个,这个上限是否合适?
- 存储空间:设置里显示已用空间;空间不足时暂停镜像并提示。具体阈值和提示文案待定。
- 「仅在电脑上」分组会越积越多:要不要默认折叠,或者移到设置里?
- 能否在同一个局域网里直接串流播放还没传完的视频,而不是只能等传完?
- 电脑的名字:电脑上报的是主机名(如「Yule's MacBook Pro」),「家里 / 公司」这类短名字要在配对成功时让用户起,或者在设置里重命名。
- 播放器的功能和叫法要和桌面端对齐:桌面端是「单句暂停」加短 / 中 / 长分句,手机端是「单句循环」;字幕时间戳要不要去掉。
- 听到哪里要不要同步回电脑?(这关系到同步是单向还是双向)
- 配对凭证:配对后电脑发给手机的长期令牌,它的格式和存储位置(放在 Keychain 还是 Keystore)。

**需要先在真机上验证的技术问题:**
- iOS 后台传输:普通 App 切到后台后很快会被挂起,要用 `URLSession` 后台传输。它能不能用在局域网地址上,需要验证。Android 需要前台服务加常驻通知。
- 找到电脑:配对时记下电脑的 ID,之后用 Bonjour/mDNS 在局域网里找它。二维码里的 IP 只用于第一次连接,因为路由器可能重新分配 IP。

**电脑端(下一版):**

- 桌面端顶栏要不要显示「N 台设备正在镜像」。
